# OpenCV_ObjectDetective_Dropball

웹캠 앞에 **실제 물건을 가져다 대면** 그 물체의 윤곽이 실시간으로 물리 충돌체가 되어,
떨어지는 공의 경로를 바꾸는 AR 게임입니다. Interactive Project 1.

공은 **오른쪽 위**에서 떨어지고 바구니는 **왼쪽 아래**에 있습니다.
가만히 두면 공은 오른쪽 바닥으로 빠지므로, 손·자·책 같은 물건을 비스듬히 대어
공을 왼쪽으로 튕겨 보내는 것이 유일한 공략법입니다.

## 실행

```bash
pip install -r requirements.txt
python game.py
```

실행하면 3초 카운트다운이 뜹니다. 그동안 **카메라 화면에서 손과 물건을 모두 치워주세요.**
이때 찍힌 화면이 "배경"으로 저장되고, 이후 배경과 달라진 부분을 물체로 인식합니다.

## 조작

| 키 | 기능 |
|---|---|
| `B` | 배경 재보정 (조명이 바뀌거나 카메라를 건드렸을 때) |
| `D` | 디버그 표시 토글 — 이진 마스크를 우측 상단에 표시 |
| `[` / `]` | **민감도** 조절 — 노이즈가 많으면 `]`, 물건이 잘 안 잡히면 `[` |
| `,` / `.` | **최소 크기** 조절 — 자잘한 덩어리가 잡히면 `.` |
| `R` | 점수 초기화 |
| `ESC` / `Q` | 종료 |

`[ ] , .` 를 누르면 디버그 표시가 자동으로 켜지고 현재 값이 화면에 나옵니다.
노이즈의 최적값은 방 조명과 배경에 따라 달라서, **마스크를 보면서 직접 맞추는 게 가장 빠릅니다.**

## 화면 구성

웹캠 영상 위에 UI를 그리므로, 배경은 살짝 어둡게 깔고(가장자리는 비네트) 게임 요소만
밝게 띄웁니다. 배경 처리는 **표시용 복사본에만** 적용되어 물체 검출에는 영향이 없습니다.

| 요소 | 의미 |
|---|---|
| 청록색 윤곽선 + 옅은 채움 | 검출된 물체. **이게 보여야 콜라이더가 등록된 것입니다** |
| 주황색 공 + 잔상 | 잔상으로 어디서 어떻게 튕겼는지 따라갈 수 있습니다 |
| `GOAL` 라벨과 아래로 흐르는 화살표 | 공을 넣어야 하는 바구니 |
| 좌상단 성공/실패 카드, 우상단 FPS | 점수와 프레임레이트 |
| 하단 키 안내 바 | 조작 키 |

성공하면 화면 테두리가 초록, 실패하면 빨강으로 한 번 번쩍입니다.
배경 인식 중에는 중앙 패널에 남은 시간이 진행 바로 표시됩니다.

색과 연출 강도는 `config.py`의 `# --- UI ---` / `# --- 색 ---` 섹션에서 조정합니다.
영상이 너무 어둡게 느껴지면 `BG_DIM`을 올리고, 비네트가 거슬리면
`VIGNETTE_STRENGTH`를 `0`으로 두면 됩니다.

## 잘 안 될 때

| 증상 | 해결 |
|---|---|
| 물건을 대도 윤곽선이 안 생김 | 배경과 색이 너무 비슷합니다. 다른 색 물건을 쓰거나 배경을 단색으로 |
| 아무것도 없는데 화면 전체가 검출됨 | 조명이 바뀌었거나 카메라가 움직였습니다. `B`로 재보정 |
| 그림자까지 물체로 잡힘 | 조명을 정면에서 주거나 `config.py`의 `DIFF_THRESHOLD`를 올리세요 |
| 자잘한 노이즈가 많음 | `D`로 마스크를 보면서 `.`로 최소 크기를 올리세요 |
| 윤곽선이 부들부들 떨림 | `DILATE_ITER`를 올리세요. **단 `MIN_CONTOUR_AREA`도 함께 올려야 합니다** |
| FPS가 30 아래로 떨어짐 | `DETECT_EVERY_N_FRAMES`를 올리거나 `MAX_CONTOURS`를 줄이세요 |
| 너무 어렵다 / 쉽다 | `BALL_RADIUS`(18)나 `BASKET_X_RATIO` 오른쪽 값(0.26)을 조절하세요 |

노이즈 문제는 **먼저 `D`로 마스크를 켜고 `]`를 눌러 민감도를 올려보세요.**
`config.py`를 고치고 재시작하는 것보다 훨씬 빠릅니다.

권장 환경: 벽이나 단색 배경을 향해 카메라를 두고, 정면 조명을 쓰면 가장 안정적입니다.

## 구조

| 파일 | 역할 |
|---|---|
| `config.py` | 모든 튜닝 상수 (해상도, 물리, 임계값, 레이아웃) |
| `camera.py` | 웹캠 래퍼. 캡처 스레드 + 좌우 반전(거울) |
| `detector.py` | 고정 배경 차분 → 윤곽 다각형 추출 |
| `world.py` | pymunk 물리 공간. 공, 벽, 바구니, 동적 콜라이더 |
| `render.py` | AR 배경 위에 게임 요소와 HUD를 그림 |
| `game.py` | 상태 머신과 메인 루프 (진입점) |

### 설계 메모

- **왜 고정 배경 차분인가**: 물체 종류를 가리지 않고 잡히기 때문입니다.
  적응형 배경 모델(`MOG2`)은 가만히 둔 물체를 몇 초 만에 배경으로 학습해
  지워버려서, 물건을 대놓고 공을 여러 번 굴리는 이 게임에는 쓸 수 없습니다.
- **좌표계**: 전 구간을 카메라 픽셀 좌표(y축 아래 방향)로 통일했습니다.
  pymunk 중력을 `(0, +900)`으로 주면 y-down이 그대로 성립해 변환 코드가 필요 없습니다.
- **자동 노출이 최대의 적**: 카메라를 연 직후 자동 노출이 수렴하는 동안
  화면 평균 밝기가 실측 **56**까지 출렁인다. 임계값이 38인데 화면 전체가
  그만큼 변하니 아무것도 없어도 전 화면이 물체로 잡힌다. 두 가지로 막았다.
  캡처 시작 시 45프레임을 버려 수렴을 기다리고(`CAMERA_WARMUP_FRAMES`),
  매 프레임 화면 밝기를 배경에 맞춰 되돌린다(`BRIGHTNESS_COMPENSATION`).
  보정을 끄면 밝기가 +40만 변해도 화면의 100%가 오검출된다.
  평균이 아니라 **중앙값**으로 보정량을 재는데, 평균은 화면에 들어온 물체
  자체에 끌려가기 때문이다.
- **콜라이더를 실제 물체보다 크게 잡는다**: `DILATE_ITER`를 2에서 4로 올렸다.
  노이즈를 줄이려는 게 아니라 **한 물체가 여러 조각으로 쪼개진 것을 하나로
  합치기** 위해서다. 조각들이 프레임마다 나타났다 사라지는 게 떨림의 주원인이었다.
  실측으로 다각형 4.7 → 1.4개, 깜빡임 -66%, 프레임간 일치도 96.2% → 97.3%.
  대신 노이즈 덩어리도 같이 커져 최소 크기 필터를 통과해버리므로
  (2384px → 5341px) `MIN_CONTOUR_AREA`를 2500에서 6000으로 함께 올렸다.
  **이 둘은 반드시 세트로 조절해야 한다.** 한쪽만 올리면 역효과다.
  얇은 물건이 걸러질 것 같지만, 팽창이 물체도 같이 부풀려서 펜(200x7px)까지
  그대로 잡힌다. 부수 효과로 공이 물체 외곽보다 살짝 바깥에서 튕겨
  "분명히 맞았는데 통과했다"는 느낌이 줄어든다.
- **캡처를 스레드로 분리한 이유**: `cap.read()`는 다음 프레임까지 33ms를
  블로킹해서, 메인 루프에서 직접 부르면 물리와 렌더까지 30fps에 묶인다.
  떼어내면 게임 루프가 **58fps**로 돌아 공 움직임이 눈에 띄게 부드러워진다.
  검출은 새 프레임이 왔을 때만 실행해 낭비가 없다.
- **멈춘 공은 속도가 아니라 이동 거리로 판정한다**: 콜라이더를 매 프레임
  새로 만들면 멈춰 있는 공도 미세하게 튕겨 속도가 순간적으로 치솟는다.
  속도로 재면 그때마다 타이머가 초기화돼 회수가 4초까지 늘어졌다.
- **pymunk 7 주의**: `space.add_collision_handler()`는 삭제되었습니다
  (`space.on_collision()`으로 대체). 이 프로젝트는 성공 판정을 기하 검사로 처리해
  충돌 핸들러를 쓰지 않습니다.
