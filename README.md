# OpenCV_ObjectDetective_Dropball

> Interactive Project 1

웹캠 앞에 **실제 물건을 가져다 대면** 그 물체의 윤곽이 실시간으로 물리 충돌체가 되어,
떨어지는 공의 경로를 바꾸는 AR 게임입니다.

공은 **오른쪽 위**에서 떨어지고 바구니는 **왼쪽 아래**에 있습니다. 가만히 두면 공은
오른쪽 바닥으로 빠지므로, 손·자·책 같은 물건을 비스듬히 대어 공을 왼쪽으로 튕겨
보내는 것이 유일한 공략법입니다. 조작 수단이 곧 게임의 목표입니다.

```
        ┌─────────────────────────┐
        │              ● ← 공      │   오른쪽 위에서 낙하
        │                         │
        │      ╱▔▔▔╲              │   ← 실제 손·물건 (웹캠 영상)
        │     (윤곽선이 충돌체)      │
        │   ↙                     │
        │ ╰──╯ ← 바구니            │   왼쪽 아래
        └─────────────────────────┘
```

## 요구 사항

Python 3.11 기준으로 개발했습니다. 웹캠이 필요합니다.

```bash
pip install -r requirements.txt
```

| 패키지 | 용도 |
|---|---|
| `opencv-python` | 카메라 입력, 배경 차분, 윤곽선 추출 |
| `numpy` | 영상 배열 연산 |
| `pygame` | 창, 렌더링, 입력 |
| `pymunk` | 2D 물리 (공, 벽, 콜라이더) |

## 실행

```bash
python game.py
```

1. **창이 뜨기까지 1~2초 걸립니다.** 카메라 자동 노출이 수렴할 때까지 기다리는
   워밍업입니다. 멈춘 게 아닙니다.
2. **3초 카운트다운 동안 화면에서 손과 물건을 모두 치워주세요.**
   이때 찍힌 화면이 "배경"으로 저장되고, 이후 배경과 달라진 부분을 물체로 인식합니다.
3. 공이 떨어지기 시작하면 물건을 대어 왼쪽 바구니로 유도하세요.

## 조작

| 키 | 기능 |
|---|---|
| `B` | 배경 재보정 — 조명이 바뀌거나 카메라를 건드렸을 때 |
| `D` | 디버그 표시 토글 — 이진 마스크를 우측 상단에 표시 |
| `[` / `]` | **민감도** 조절 — 노이즈가 많으면 `]`, 물건이 잘 안 잡히면 `[` |
| `,` / `.` | **최소 크기** 조절 — 자잘한 덩어리가 잡히면 `.` |
| `R` | 점수 초기화 |
| `ESC` / `Q` | 종료 |

`[ ] , .` 를 누르면 디버그 표시가 자동으로 켜지고 현재 값이 화면에 나옵니다.
**노이즈의 최적값은 방 조명과 배경에 따라 달라서, 마스크를 보면서 직접 맞추는 것이
config.py를 고치고 재시작하는 것보다 훨씬 빠릅니다.**

## 화면 구성

웹캠 영상 위에 UI를 그리므로, 배경은 살짝 어둡게 깔고(가장자리는 비네트) 게임 요소만
밝게 띄웁니다. 배경 처리는 **표시용 복사본에만** 적용되어 물체 검출에는 영향이 없습니다.

| 요소 | 의미 |
|---|---|
| 청록색 윤곽선 + 옅은 채움 | 검출된 물체. **이게 보여야 콜라이더가 등록된 것입니다** |
| 주황색 공 + 잔상 | 잔상으로 어디서 어떻게 튕겼는지 따라갈 수 있습니다 |
| GOAL 라벨과 아래로 흐르는 화살표 | 공을 넣어야 하는 바구니 |
| 좌상단 성공/실패 카드, 우상단 FPS | 점수와 프레임레이트 |
| 하단 키 안내 바 | 조작 키 |

성공하면 화면 테두리가 초록, 실패하면 빨강으로 한 번 번쩍입니다.

윤곽선이 **실제 물체보다 다소 크게** 그려지는 것은 의도된 동작입니다.
아래 [콜라이더를 실제 물체보다 크게 잡는다](#콜라이더를-실제-물체보다-크게-잡는다)를
참고하세요.

색과 연출 강도는 config.py의 `# --- UI ---` / `# --- 색 ---` 섹션에서 조정합니다.
영상이 너무 어둡게 느껴지면 `BG_DIM`을 올리고, 비네트가 거슬리면
`VIGNETTE_STRENGTH`를 0으로 두면 됩니다.

## 동작 원리

### 검출 파이프라인 (detector.py)

매 카메라 프레임마다 실행됩니다.

```
카메라 프레임
  ↓ grayscale + GaussianBlur(21)      센서 노이즈 억제
  ↓ 전역 밝기 보정 (중앙값 기준)         자동 노출·조명 변화 상쇄
  ↓ absdiff(배경)                      배경과 다른 부분만 남김
  ↓ threshold(38)                      이진 마스크화
  ↓ MORPH_OPEN(7)                      점 노이즈 제거
  ↓ MORPH_CLOSE(7) + dilate(x4)        끊긴 조각을 하나로 병합
  ↓ 시간 평균 (EMA 0.45)                한두 프레임 깜빡이는 노이즈 제거
  ↓ findContours + 면적 필터(6000)      큰 것부터 최대 6개
  ↓ approxPolyDP                       꼭짓점을 줄여 물리 부하 감소
다각형 목록
```

### 콜라이더 변환 (world.py)

각 다각형의 이웃 꼭짓점을 이어 `pymunk.Segment` 체인(두께 3px)으로 만들어
정적 바디에 붙입니다. 매 검출마다 통째로 교체합니다.

**공이 이미 안에 들어와 있는 도형은 그 프레임만 건너뜁니다.** 그대로 생성하면
pymunk가 겹친 공을 강하게 밀어내 순간이동이 생깁니다.

### 판정

- **성공**: 공 중심이 바구니 내부 사각형 안에 들어오면 (기하 검사)
- **실패**: 화면 아래로 이탈 / 12px 안에 1.5초 이상 머무름 / 12초 경과

## 잘 안 될 때

| 증상 | 해결 |
|---|---|
| 물건을 대도 윤곽선이 안 생김 | 배경과 색이 너무 비슷합니다. 다른 색 물건을 쓰거나 배경을 단색으로 |
| 아무것도 없는데 화면 전체가 검출됨 | 조명이 바뀌었거나 카메라가 움직였습니다. `B`로 재보정 |
| 그림자까지 물체로 잡힘 | 조명을 정면에서 주거나 `]`로 민감도를 올리세요 |
| 자잘한 노이즈가 많음 | `D`로 마스크를 보면서 `.`로 최소 크기를 올리세요 |
| 윤곽선이 부들부들 떨림 | `DILATE_ITER`를 올리세요. **단 `MIN_CONTOUR_AREA`도 함께 올려야 합니다** |
| FPS가 30 아래로 떨어짐 | `DETECT_EVERY_N_FRAMES`를 올리거나 `MAX_CONTOURS`를 줄이세요 |
| 너무 어렵다 / 쉽다 | `BALL_RADIUS`나 `BASKET_X_RATIO` 오른쪽 값을 조절하세요 |
| 카메라를 못 연다 | 다른 프로그램이 웹캠을 쓰고 있는지 확인하세요 |

**노이즈 문제는 먼저 `D` → `]`를 몇 번 눌러보세요.** 대부분 여기서 해결됩니다.

권장 환경: 벽이나 단색 배경을 향해 카메라를 두고, 정면 조명을 쓰면 가장 안정적입니다.

## 주요 설정값

전부 config.py에 모여 있습니다. 자주 만지는 것만 추립니다.

| 상수 | 기본값 | 의미 |
|---|---|---|
| `DIFF_THRESHOLD` | 38 | 배경과 이만큼 밝기가 다르면 물체로 인정 (게임 중 `[ ]`) |
| `MIN_CONTOUR_AREA` | 6000 | 이보다 작은 덩어리는 노이즈로 간주 (게임 중 `, .`) |
| `DILATE_ITER` | 4 | 팽창 횟수. `MIN_CONTOUR_AREA`와 **세트로** 조절 |
| `MASK_SMOOTHING` | 0.45 | 낮출수록 안정적이지만 반응이 느려짐 |
| `BALL_RADIUS` | 18 | 키울수록 쉬워지고 콜라이더 관통도 줄어듦 |
| `GRAVITY` | (0, 900) | 낙하 속도 |
| `BASKET_X_RATIO` | (0.0, 0.26) | 바구니 가로 범위. 오른쪽 값을 키우면 쉬워짐 |
| `CAMERA_WARMUP_FRAMES` | 45 | 자동 노출 수렴 대기. 시작이 느리면 줄이세요 |
| `DISPLAY_SCALE` | 1.5 | 창 크기 배율 (960×720) |

## 설계 메모

만들면서 실제로 부딪힌 문제와 그 해결입니다. 수치는 모두 이 프로젝트에서 직접
측정한 값입니다.

### 왜 고정 배경 차분인가

물체 종류를 가리지 않고 잡히기 때문입니다. 손인지 책인지 자인지 구분할 필요 없이
"배경과 다르니까 뭔가 있다"로만 판단합니다.

적응형 배경 모델(MOG2)은 쓸 수 없습니다. **물체를 가만히 두면 몇 초 만에 배경으로
학습해 지워버립니다.** 물건을 대놓고 공을 여러 번 굴려야 하는 이 게임에는 치명적입니다.
대신 조명이 바뀌면 `B`로 재보정해야 하는 부담을 집니다.

### 자동 노출이 최대의 적

가장 큰 노이즈 원인은 센서 노이즈가 아니라 **카메라의 자동 노출**이었습니다.

카메라를 연 직후 자동 노출이 수렴하는 동안 화면 평균 밝기가
**63.9 → 119.8, 변동폭 56**까지 출렁입니다. 임계값이 38인데 화면 전체가 그만큼
변하니, 아무것도 없어도 전 화면이 물체로 잡힙니다. 게다가 배경 보정은 시작 3초 뒤 —
하필 그 수렴 구간이었습니다.

두 가지로 막았습니다.

| 대책 | 내용 |
|---|---|
| `CAMERA_WARMUP_FRAMES` | 캡처 시작 시 45프레임을 버려 수렴을 기다림 |
| `BRIGHTNESS_COMPENSATION` | 매 프레임 화면 밝기를 배경에 맞춰 되돌림 |

보정을 끄면 밝기가 **+40만 변해도 화면의 100%가 오검출**되지만, 켜면 **0%**입니다.

보정량은 평균이 아니라 **중앙값**으로 잽니다. 평균은 화면에 들어온 물체 자체에
끌려가기 때문입니다. 물체가 화면 절반을 넘지 않는 한 중앙값은 배경 쪽에 남습니다.

> 카메라 노출을 수동으로 고정하는 방법도 시도했다가 뺐습니다. 정상 상태 변동이
> 1.5에서 6.9로 **오히려 나빠졌습니다.** 적정 노출값이 환경마다 달라 일반화할 수
> 없습니다.

### 콜라이더를 실제 물체보다 크게 잡는다

`DILATE_ITER`를 2에서 4로 올려 윤곽을 실제 물체보다 부풀립니다.

**노이즈를 줄이려는 게 아니라, 한 물체가 여러 조각으로 쪼개진 것을 하나로 합치기
위해서입니다.** 그 조각들이 프레임마다 나타났다 사라지는 것이 윤곽선 떨림의
주원인이었습니다. 실제 웹캠 150프레임을 녹화해 같은 입력으로 비교한 결과입니다.

| 지표 | 팽창 2 / 최소 2500 | **팽창 4 / 최소 6000** |
|---|---|---|
| 다각형 개수 | 4.7 | **1.4** (-70%) |
| 깜빡임 (표준편차) | 1.44 | **0.49** (-66%) |
| 프레임간 윤곽 일치도 | 96.2% | **97.3%** |
| 노이즈 조각 | 0.40/프레임 | **0.13** (-67%) |

**단, 팽창만 올리면 역효과입니다.** 노이즈 덩어리도 같이 커져(2384px → 5341px)
최소 크기 필터를 통과해버려 노이즈가 0.40 → 0.87로 **늘어납니다.** 그래서
`MIN_CONTOUR_AREA`를 2500에서 6000으로 함께 올렸습니다.
**이 둘은 반드시 세트로 조절해야 합니다.**

최소 크기를 올리면 얇은 물건이 걸러질 것 같지만, 팽창이 물체도 같이 부풀려서
상쇄됩니다. 자, 펜(200×7px), 명함 모두 그대로 잡히는 것을 확인했습니다.

부수 효과로 공이 물체 외곽보다 살짝 바깥에서 튕겨, "분명히 맞았는데 통과했다"는
느낌이 줄어듭니다.

참고로 효과가 없었던 대안들입니다. 팽창만이 결정적이었습니다.

| 시도 | 다각형 개수 | 일치도 |
|---|---|---|
| 시간 평균 강화 (0.45 → 0.25) | 4.7 → 4.7 | 96.2% → 96.4% |
| 윤곽 단순화 강화 (eps 0.008 → 0.025) | 4.7 → 4.7 | 96.2% → 96.2% |
| 닫기 커널 확대 (7 → 11) | 4.7 → 4.0 | 96.2% → 96.1% |

### 캡처를 스레드로 분리한 이유

`cap.read()`는 다음 프레임이 올 때까지 **33ms를 블로킹**합니다. 메인 루프에서 직접
부르면 물리와 렌더까지 카메라 속도(30fps)에 묶여 공 움직임이 끊겨 보입니다.

캡처를 스레드로 떼어내면 게임 루프가 **58fps**로 돌아갑니다. 검출은 새 프레임이
왔을 때만 실행해 낭비가 없습니다.

렌더러는 서피스를 미리 잡아두고 픽셀만 덮어씁니다. 매 프레임 `make_surface`로
새로 할당하던 것을 `blit_array` 재사용으로 바꿔 draw_frame이
**4.35ms → 2.02ms**가 되었습니다. (`cv2.transpose`도 시도했지만 전체 복사가 일어나
오히려 느렸습니다.)

### 좌표계

전 구간을 **카메라 픽셀 좌표(640×480, y축 아래 방향)**로 통일했습니다.

pymunk는 축 방향에 무관하게 동작하므로 중력을 `(0, +900)`으로 주면 y-down이 그대로
성립합니다. OpenCV·pygame과의 좌표 변환 코드가 전혀 필요 없습니다. 화면 확대는
**그리는 순간에만** `DISPLAY_SCALE`을 곱합니다.

### 멈춘 공은 속도가 아니라 이동 거리로 판정한다

콜라이더를 매 프레임 새로 만들면 멈춰 있는 공도 미세하게 튕겨 속도가 순간적으로
치솟습니다. 속도로 "멈췄다"를 판정하면 그때마다 타이머가 초기화돼 회수가
**4초까지** 늘어졌습니다. `STILL_DISTANCE`(12px) 안에 머문 시간으로 재도록 바꿔
**1.5초**로 정상화했습니다.

### 바구니를 왼쪽 벽에 붙인 이유

처음에는 바구니를 화면 왼쪽 끝에서 조금 띄웠는데, 그 사이 38px 틈으로 공이 빠져
사라졌습니다. 판정상 실패는 맞지만 버그처럼 보여서 벽에 붙였습니다.

### pymunk 7 주의

`space.add_collision_handler()`는 **삭제되었습니다**
(`space.on_collision()`으로 대체). 온라인 예제 대부분이 구버전이라 그대로 쓰면
깨집니다.

이 프로젝트는 성공 판정을 기하 검사로 처리해 충돌 핸들러를 아예 쓰지 않습니다.
API 변경 리스크를 피하고 코드도 더 짧습니다.

## 앞으로 붙일 수 있는 것

현재 구조를 갈아엎지 않고 덧붙일 수 있도록 설계했습니다.

- 레벨별 바구니 위치 이동 → `BASKET_*_RATIO`를 레벨 데이터로 분리
- 제한 시간 / 목표 개수 / 최고 점수 저장 → game.py 상태 머신에 상태 추가
- 공 여러 개 동시 낙하 → `World`의 공 단일 참조를 리스트로 변경
- 효과음·파티클 → render.py에 국한
